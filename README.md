# Telegram GUI Tool

**Готовая Windows-версия:** `dist\TelegramGuiTool.exe` или ZIP `dist\TelegramGuiTool-1.0.0-windows-x64.zip`. Python для EXE не нужен. [Полное руководство пользователя и техническое описание](MANUAL.md) объясняет установку, хранение данных, перенос старой базы, устройство модулей, сборку и диагностику.

У EXE данные находятся в `%LOCALAPPDATA%\TelegramGuiTool`; при запуске исходников — в папке проекта, как описано ниже. В поставку не включаются рабочая база, журналы и ваши TXT/экспорты. Перед переходом с исходников прочитайте раздел о переносе базы в полном руководстве.

Локальное приложение для Windows 10 x64 и Python 3.11/3.12. PySide6 предоставляет GUI, SQLite хранит очередь, QThread выполняет чтение TXT, обработку и экспорт. Локальный тест работает без интернета; режим реальной переписки использует запущенный и авторизованный пользователем Telegram Desktop с подключением к сети. Telegram API, учётные данные и автоматизация авторизации не используются.

## Установка и запуск — PowerShell

Установите Python 3.11 или 3.12 x64 с python.org, отметив **Add Python to PATH**. Откройте PowerShell в каталоге `telegram_gui_tool`:

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Активация окружения не нужна; менять ExecutionPolicy не требуется. Если окружение уже создано в родительской папке, используйте `..\.venv\Scripts\python.exe`.

При запуске по умолчанию выбран режим **Отправка TXT и чтение ответов**, в том числе при восстановлении очереди другого режима. Отправка начинается только после нажатия «Начать» и подтверждения. Минимальный размер окна — **480 × 420**. При уменьшении ширины панели файла и настроек переходят в одну колонку, кнопки — в несколько строк, длинные подписи переносятся внутри карточек. При недостатке высоты доступна вертикальная прокрутка всего интерфейса; содержимое предпросмотра и журнала имеет свою прокрутку. Горизонтальная прокрутка страницы не нужна. Выпадающий список оформлен вместе с меню, поддерживает клавиатуру; слишком длинное выбранное название сокращается многоточием и доступно полностью в подсказке.

## Как пользоваться

1. Нажмите **Выбрать TXT**. Для первого запуска используйте `data\sample.txt` с фиктивными идентификаторами.
2. По умолчанию пустые и пробельные строки удаляются. Чтобы сохранить их отдельными заданиями, снимите флажок **до загрузки**. Исходный файл не изменяется; пробелы в непустых строках сохраняются. Видны кодировка, количество записей и первые 10 строк.
3. Выберите локальный режим и нажмите **Начать**, затем подтвердите запуск. Каждая строка создаёт фиктивное JSON-сообщение, парсер проверяет его структуру, результат сохраняется в SQLite.
4. **Пауза** приостанавливает обработку перед следующим действием в Telegram и во время ожидания между строками. **Продолжить** снимает паузу: в режимах Telegram сначала даётся 5 секунд для возврата в его окно. После остановки и перезапуска эта же кнопка запускает оставшуюся очередь с подтверждением. **Остановить** отменяет ожидания и отсчёт продолжения, будит приостановленный поток и сохраняет состояние. Уже выполняющийся UIA-вызов завершается перед остановкой; неопределённая отправка автоматически не повторяется.
5. **Экспорт** позволяет выбрать JSON-файл, в том числе во время обработки. Отчёт содержит согласованный снимок запуска и всех задач, Unicode сохраняется в UTF-8 без ASCII-экранирования. Запись выполняется через временный файл с атомарной заменой результата.
6. **Отменить загрузку** отменяет чтение/импорт TXT; существующая очередь остаётся доступной. Закрытие окна во время работы ожидает безопасного завершения фоновых операций. При каждом открытии программы поле предпросмотра и путь к TXT пустые: прошлые входные строки не выводятся автоматически. Сохранённая очередь, настройки и результаты SQLite остаются доступны для продолжения и экспорта.

Кнопки включаются по состоянию приложения. Журнал в окне показывает операции без содержимого исходных строк. Файловый журнал `logs\app.log` содержит время, уровень и traceback ошибок, ротация — 2 МБ и 3 резервных файла. Не используйте реальные персональные данные в тестовых файлах: TXT, предпросмотр, SQLite и отчёты содержат входные строки и результаты в открытом виде.

Режим и кнопку выбора TXT можно использовать после нажатия «Начать», включая обратный отсчёт и работающую очередь. Открытие списка режимов или выбора файла отменяет отсчёт и запрашивает корректную остановку. Новый TXT загружается после сохранения текущей операции. При запуске другого режима создаётся отдельная очередь только из записей pending; прежние результаты сохраняются, завершённые записи не повторяются. Остановленная до попытки отправки запись возвращается в pending, а запись с неопределённой возможной отправкой автоматически не повторяется. Перезапуск приложения для смены режима или файла не требуется.

## Очередь и восстановление

### Отправка TXT и чтение настоящих ответов

1. Перезапустите приложение после обновления. Заново загрузите TXT для отдельной очереди реальной отправки.
2. Выберите третий режим **Отправка TXT и чтение ответов** и укажите **Username получателя**, например `@my_test_bot`. Ссылка, номер телефона и отображаемое имя не подходят.
3. Запустите Telegram, вручную откройте нужную переписку и разверните окно. Желательно заранее открыть правую боковую панель профиля получателя, где виден username. Поддерживаются наблюдённые UIA-элементы Telegram Desktop и подписи RU/EN. Не используйте всплывающий профиль поверх чата. Уберите черновики, диалоги и предупреждения вручную.
4. Нажмите **Начать**. Подтверждение явно показывает получателя. После него переключитесь в Telegram за 5 секунд.
5. Программа работает только с уже открытой перепиской: не заполняет поиск и не выбирает чаты. Username проверяется один раз при запуске обработки. Если боковой профиль ещё не открыт, программа нажимает кнопку информации текущего чата; затем проверяет точный username рядом с подписью Username. При несовпадении или недоступности элементов отправка не выполняется. В дальнейших итерациях username и заголовок окна не проверяются; сохраняются проверки активного окна и блокирующих диалогов. Изменение счётчика или статуса в заголовке не останавливает очередь. Во время обработки не переключайте переписку вручную. При новом запуске или продолжении очереди после остановки выполняется новая стартовая проверка.
6. Каждая непустая строка отправляется отдельным сообщением. Используется UIA ValuePattern для ввода и кнопка отправки, а не Enter (настройка Enter в Telegram не влияет). При отсутствии InvokePattern клик выполняется по найденному UIA-элементу; фиксированных координат нет. Буфер обмена не меняется.
7. Цикл: **отправить строку → ждать 3 секунды → прочитать входящие → ждать 2 секунды → следующая строка**. Две задержки настраиваются полями **После отправки до чтения, с** и **После чтения до следующей строки, с** (0–3600 секунд). Отдельного окна сбора на 30 секунд и завершения по паузе нет. Чтение — один снимок истории после первой задержки; при временной ошибке UIA может повториться само чтение. Ответами считаются все новые входящие текстовые сообщения после подтверждённого исходящего сообщения. Исходящие и прежние входящие не включаются; одинаковые тексты разных сообщений сохраняются отдельно.
8. Ответы попадают в `tasks.result.messages`, доступны через **Экспорт**. Частичный результат сохраняется по мере поступления.

**Разброс задержек ±, с** добавляет независимое равномерное отклонение к обеим задержкам каждой итерации. Например, при базовой задержке 2 секунды и разбросе 0,2 секунды получится значение в диапазоне 1,8–2,2 секунды. При нуле задержки остаются фиксированными; отрицательного времени ожидания не бывает. Настройка сохраняется в SQLite, фактическая задержка до чтения — в `result.reply_delay_seconds`. Это настройка темпа, она не гарантирует отсутствие ограничений Telegram и не заменяет соблюдение правил сервиса и условий получателя.

После ввода текстовый курсор устанавливается в конец поля через UIA TextPattern. Если TextPattern не поддерживает выделение, выполняется Ctrl+End только в подтверждённо сфокусированном поле Telegram. Положение указателя мыши для этого не меняется.

Новое исходящее сообщение определяется сравнением текстов, порядка и количества вхождений в истории до/после отправки. Смена или повторное использование UIA-идентификаторов строк не считается признаком нового сообщения. Если исходящее ещё не появилось в снимке, выполняются до двух дополнительных чтений с паузой 0,2 секунды; кнопка отправки повторно не нажимается. При неоднозначности сохраняются только диагностические количества строк и совпадений в `result.confirmation`, без дополнительной копии истории. Если вся доступная история заменилась идентичной последовательностью и новизну исходящего доказать нельзя, обработка останавливается.

После чтения задача сохраняется и очередь продолжается, если исходящая отправка подтверждена через UIA. `messages` содержит любое число полученных текстов, включая пустой список при отсутствии ответа. `completion_reason=snapshot_after_delay` означает чтение снимка после заданной задержки. `reply_complete=false` не является ошибкой задачи: программа не определяет, закончил ли собеседник отвечать.

При потере фокуса, блокирующем диалоге или неподтверждённой отправке очередь останавливается. Запрос паузы обрабатывается до проверки фокуса, поэтому нажатие кнопки «Пауза» само по себе не должно прерывать очередь. Во время паузы новые UI-действия не выполняются. Для продолжения после нажатия кнопки есть 5 секунд на возврат в Telegram. Остановка во время ожидания сохраняет частичный ответ и ошибку остановки. Временный сбой чтения обновляющейся UIA-истории повторяется до трёх раз; отправка никогда не повторяется. Диагностика сохраняет этап, тип ошибки и HRESULT без содержимого переписки.

В таблице `run_options` сохраняются режим, username и настройки задержек. Кнопки «− / +» изменяют каждое числовое поле на 0,1 секунды без выделения текста. Значение также можно ввести вручную. Задержки можно менять перед продолжением текущей очереди; для другого получателя загрузите TXT в новый запуск. Существующие БД обновляются автоматически, данные не удаляются. При переходе со старой схемы ожидания устанавливаются задержки 3 и 2 секунды; последующие изменения сохраняются. До нажатия отправки SQLite сохраняет `send_attempted=true`. После сбоя такая задача становится failed и **не отправляется автоматически повторно**, даже если неизвестно, успел ли клиент отправить сообщение. Проверяйте чат перед ручным повтором. Это предотвращает автоматический дубль, но не является гарантией exactly-once на стороне Telegram.

Ограничения: читается доступная UIA-история текстовых сообщений. Медиа, скачивание файлов, каналы без возможности отправки, темы и групповые ответы нескольких участников отдельным сценарием не поддерживаются. Входящие относятся к строке по порядку и времени, а не по Telegram reply-to ID: используйте спокойный тестовый чат. Сообщения, пришедшие после снимка истории, не добавляются к уже завершённому результату; для медленного ответа увеличьте первую задержку. Исходящее сообщение должно оставаться доступным через UIA для подтверждения отправки и границы ответа. Код не прокручивает историю и не обходит ограничения клиента. Если UIA не раскрывает точный username, направление сообщения или кнопку отправки, нужен другой поддерживаемый вид окна/версия клиента, а не отключение проверки.

Полная реальная отправка не выполнялась при разработке: получатель для тестового сообщения не был указан в чате с разработчиком. Структура UI проверена на запущенном Telegram без отправки сообщений; логика отправки, чтения и восстановления проверяется автоматическими тестами с подменой UIA.

База `data\progress.db` создаётся автоматически. Таблицы `runs` и `tasks` содержат поля из задания, внешние ключи и индекс очереди. Задачи проходят `pending → processing → completed/failed/skipped`; каждый переход транзакционный. Статус `skipped` поддерживается хранилищем, текущий сценарий обрабатывает все строки без пропуска.

После перезапуска последняя незавершённая очередь восстанавливается без исходного TXT. Задачи `processing`, оставшиеся после аварийного завершения до отметки отправки, возвращаются в `pending`; задачи с отметкой `send_attempted` становятся failed с сохранением частичного результата. Завершённые и ошибочные повторно не выбираются. Ошибочные задачи остаются в отчёте. Для повторного теста всего файла загрузите его заново — это создаёт новый запуск. Старые запуски остаются в БД; интерфейс показывает текущий запуск, отдельного браузера истории нет.

При закрытии во время загрузки уже зафиксированный новый запуск может остаться в БД и будет доступен при следующем старте. QLockFile запрещает запуск второго экземпляра на ту же БД через main.py; не открывайте эту БД сторонним обработчиком во время работы. Временные метки БД/JSON используют UTC с явным смещением; журнал GUI — локальное время.

## Проверка Telegram Desktop и её ограничения

Второй режим **не отправляет сообщения** и не читает ответы из чатов. Он добавляет к локальному сценарию настоящую проверку окна через pywinauto/UI Automation. После подтверждения есть 5 секунд, чтобы вручную активировать Telegram. Приложение ищет процесс `Telegram.exe`, проверяет активный HWND, видимость, доступность и перечисляет доступные элементы управления. В результат попадают только типы и количества элементов, без заголовков и текстов чатов. Фокус проверяется до и во время обхода. При потере фокуса, предупреждении или неожиданном состоянии текущая задача отмечается failed, дальнейшая очередь останавливается.

Для управления используйте кнопки «Пауза», «Продолжить» и «Остановить»: запросы управления учитываются до следующей проверки фокуса. После продолжения переключитесь обратно в Telegram за 5 секунд. Переход в другие приложения без запроса паузы по-прежнему может вызвать остановку по потере фокуса.

Доступность элементов зависит от версии Telegram, Windows и настроек accessibility. Qt может не раскрывать дочерние элементы — пустой список не подтверждает доступность чатов. Проверка останавливается при видимом модальном окне (`WindowPattern.IsModal`) или стандартном Win32-диалоге (`#32770`), включая само активное окно. Тексты элементов не читаются: слова «ошибка», «предупреждение», `error`, `warning` в переписке не считаются признаком ошибки платформы. Нестандартные баннеры Qt без доступных признаков диалога этим способом не распознаются; успешная проверка означает только проверку доступных UI-элементов, а не отсутствие любых предупреждений. Этот режим остаётся только для чтения. UIA-вызовы стороннего процесса могут задерживаться дольше настроенного ожидания; принудительное завершение потока не применяется.

В третьем режиме реализован настоящий обмен, описанный выше; локальный тест и второй режим по-прежнему не отправляют сообщения. PyAutoGUI остаётся резервной зависимостью. `clipboard_manager.py` предоставляет явные операции с проверкой и таймаутом; основные сценарии не меняют Clipboard. Автоматические тесты не отправляют сообщения в Telegram.

## Кодировки и ошибки

Поддерживаются UTF-8, UTF-8 BOM и Windows-1251. Сначала выполняется строгая проверка UTF-8, затем CP1251; UTF-16, NUL, некоторые управляющие символы и некорректный BOM отклоняются. Надёжно отличить произвольную однобайтную кодировку от CP1251 без метаданных нельзя: допустимые CP1251 байты могут быть неверно распознаны. Проверяйте предпросмотр. Файл загружается в память; объём ограничен доступной RAM.

- **Python не найден**: перезапустите терминал после установки и проверьте PATH.
- **Ошибка установки пакетов**: проверьте интернет, доступ к PyPI и соответствие Python x64.
- **Telegram не найден/неактивен**: запустите официальный Telegram Desktop и активируйте его во время обратного отсчёта. Store/нестандартные сборки с другим именем процесса могут не поддерживаться.
- **Access denied / UIA**: запускайте Telegram и инструмент с одинаковыми правами, предпочтительно без администратора.
- **SQLite locked / ошибка записи**: закройте второй экземпляр, проверьте права на `data`, свободное место. Не удаляйте БД для исправления без резервной копии.
- **Clipboard занят**: повторите явную операцию после закрытия приложения, удерживающего буфер; таймаут выдаёт ClipboardError.
- **Ошибка JSON**: проверьте путь и доступ к целевой папке; незавершённая запись не заменяет старый отчёт.

Для окружения в родительской папке замените путь на `..\.venv\Scripts\python.exe`. На безэкранной машине можно задать `$env:QT_QPA_PLATFORM = 'offscreen'` перед тестами; перед обычным запуском удалите переменную: `Remove-Item Env:QT_QPA_PLATFORM`.

Тесты проверяют кодировки, отмену, пустые строки, парсер, транзакции, статусы, восстановление, Unicode JSON, промежуточный экспорт, паузу/остановку/продолжение, подтверждение запуска и полный цикл через настоящее окно PySide6 с временной SQLite. Диалоги подтверждения и выбора пути в тестах подменяются. Ошибка Telegram проверяется подменой контроллера; реальный Telegram требует ручной проверки на целевой машине. Все данные тестов фиктивные.

Проверка разработки: Python 3.12.8, PySide6 6.12.0, pywinauto 0.6.9; зависимости установлены в `.venv` родительского каталога, `pip check` не выявил конфликтов. Дополнительно `tests\verify_startup.py` проверяет основной `main()`, загрузку трёх строк примера и сохраняет изображение окна `exports\gui_preview.png`; проверка отрисовки выполнена с `QT_QPA_PLATFORM=offscreen`. Реальное окно Telegram и совместимость на отдельной Windows 10 машине в этой проверке не тестировались.

`tests\verify_layout.py` проверяет геометрию и сохраняет изображения интерфейса и списка выбора в `exports\layout` для размеров 480×420, 640×480, 800×600, 1080×900, 1440×1000 и 1280×520. Unit-тесты компоновки дополнительно проверяют длинное имя файла без пробелов, перенос подписей, доступность элементов через прокрутку и выбор режима клавиатурой.
