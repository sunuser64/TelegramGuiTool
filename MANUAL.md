# Telegram GUI Tool 1.0.0

## Полное руководство: готовая программа, работа с данными и техническое устройство

Это приложение для Windows 10 x64. Оно берёт строки из TXT, отправляет их в уже открытую переписку Telegram Desktop и сохраняет прочитанные текстовые ответы. Для проверки есть локальный режим без Telegram и режим чтения сведений об окне без отправки сообщений.

Инструмент управляет обычным интерфейсом Telegram. Авторизация, Bot API, MTProto, `api_id` и `api_hash` не используются. Войти в Telegram нужно самостоятельно. Режим отправки выбран по умолчанию, но сообщения начнут отправляться только после нажатия **Начать** и подтверждения.

## 1. Установка и первый запуск EXE

Распакуйте `TelegramGuiTool-1.0.0-windows-x64.zip` в обычную папку. Запустите `TelegramGuiTool.exe` двойным щелчком. Python, pip и виртуальное окружение для готового EXE не нужны. Telegram Desktop устанавливается отдельно. Обычно права администратора не требуются; лучше запускать Telegram и инструмент с одинаковым уровнем прав.

Состав поставки:

| Файл | Для чего нужен |
| --- | --- |
| `TelegramGuiTool.exe` | Программа со встроенным Python и библиотеками |
| `MANUAL.md` | Это руководство простым языком |
| `README.md` | Подробности сценариев, исходников и известных ограничений |
| `sample.txt` | Три фиктивные записи для первого теста |
| `build-info.json` | Дата сборки, версии компонентов, размер EXE и его SHA-256 |
| `SHA256SUMS.txt` | Контрольная сумма EXE |
| `requirements-lock.txt` | Точный состав Python-окружения сборки |

Приложение собрано как один файл, без установщика и консольного окна. При запуске загрузчик распаковывает библиотеки во временную папку. Это занимает время: появление окна может задержаться на несколько секунд. Рабочая база туда не записывается.

Целевая система — Windows 10 x64. Эта сборка не предназначена для Windows x86, Windows 7, Linux или macOS. EXE не подписан цифровым сертификатом издателя. Контрольная сумма подтверждает совпадение с конкретной сборкой, но не заменяет подпись. Её можно проверить в PowerShell:

```powershell
Get-FileHash .\TelegramGuiTool.exe -Algorithm SHA256
```

Для первого теста выберите `sample.txt`, переключитесь в **Локальный тест** и нажмите **Начать**. Должны завершиться три задачи без ошибок. В этом режиме ответы фиктивные, например `Test response: test_001`. Затем проверьте **Экспорт JSON**. Это проверит приложение без настоящей переписки.

## 2. Постоянная папка данных

У EXE по умолчанию используется:

```text
%LOCALAPPDATA%\TelegramGuiTool\
  data\progress.db     очередь, настройки запусков и результаты
  data\sample.txt      встроенный пример
  data\app.lock        блокировка второго экземпляра
  logs\app.log         журнал
  logs\app.log.1 ...   резервные журналы
  exports\            начальная папка диалога экспорта
```

Обычно `%LOCALAPPDATA%` — это `C:\Users\имя_пользователя\AppData\Local`. Открыть папку можно так:

```powershell
explorer "$env:LOCALAPPDATA\TelegramGuiTool"
```

Перемещение или замена EXE не перемещает и не удаляет эту папку. Не нужно искать временный каталог `_MEI...`: в нём только распакованные компоненты.

**При запуске исходников данные по-прежнему находятся рядом с исходниками**, в `telegram_gui_tool\data`, `logs`, `exports`. Поэтому переход на EXE по умолчанию создаёт отдельное хранилище. Старый прогресс не потерян, но его нужно перенести по разделу 8, если он нужен в EXE.

Можно явно задать другой каталог, например для переносного варианта:

```powershell
$env:TGNL_DATA_DIR = 'D:\TelegramToolData'
.\TelegramGuiTool.exe
```

Внутри него появятся `data`, `logs` и `exports`. Переменная действует только в текущем PowerShell и запущенных из него процессах. Вернуть стандартный путь:

```powershell
Remove-Item Env:TGNL_DATA_DIR
```

Не используйте одну базу одновременно из нескольких обработчиков. Для каждой папки данных применяется отдельная блокировка QLockFile. Не удаляйте `app.lock` у работающей программы.

## 3. Подготовка файла и Telegram

Подготовьте TXT: одна строка — одна задача и одно исходящее сообщение. Поддерживаются UTF-8, UTF-8 BOM и Windows-1251. Оригинал не меняется. Пустые и пробельные строки по умолчанию пропускаются; флажок влияет на следующую загрузку, а не на уже созданную очередь.

Файл читается порциями, но итоговый список строк хранится в памяти. Практический предел зависит от RAM и размера базы. Просмотр показывает первые десять строк. Двоичные файлы, UTF-16, NUL и неподходящие управляющие символы отклоняются. Табуляция может быть прочитана, но строка с ней не будет отправлена в настоящем режиме. Многострочное сообщение в одной записи не поддерживается.

Сначала программа строго проверяет UTF-8, затем CP1251. Отличить любую однобайтную кодировку от CP1251 без метаданных невозможно: проверяйте предпросмотр, а при проблемах пересохраните файл в UTF-8.

Для настоящей отправки:

1. Самостоятельно войдите в официальный Telegram Desktop и откройте согласованную переписку.
2. Разверните окно, уберите предупреждения и диалоги. Черновик сохраните или очистите вручную.
3. Желательно заранее открыть боковой профиль получателя, где виден `@username`. Всплывающий профиль не должен закрывать поле ввода.
4. В программе выберите TXT и режим **Отправка TXT и чтение ответов**.
5. Введите username, например `@my_test_bot`. Ссылка `https://t.me/...`, телефон и отображаемое имя не подходят.
6. Нажмите **Начать**, проверьте получателя в подтверждении и за пять секунд переключитесь в Telegram.

Инструмент не ищет получателей и не выбирает чаты. Username проверяется при запуске обработчика. Если профиль закрыт, инструмент может нажать кнопку информации текущей переписки. При несовпадении имени отправка не начинается.

В дальнейших итерациях username и заголовок повторно не проверяются. Это выбранная схема работы; **вручную менять чат во время обработки нельзя**. Фокус окна и блокирующие диалоги проверяются. Снятие обычной паузы продолжает тот же обработчик, а запуск после остановки выполняет новую стартовую проверку.

Второй режим — **Проверка окна Telegram** — ничего не отправляет: он обрабатывает фиктивные ответы и дополнительно считает доступные элементы активного окна. Успешный такой тест не доказывает работоспособность настоящего обмена.

## 4. Кнопки, смена режима и восстановление

| Кнопка | Что делает |
| --- | --- |
| Выбрать TXT | Создаёт отдельный запуск из файла |
| Отменить загрузку | Прерывает чтение/импорт, прежняя очередь сохраняется |
| Начать | Запрашивает подтверждение и обрабатывает оставшиеся записи |
| Пауза | Приостанавливает перед следующим UI-действием или во время ожидания между строками |
| Продолжить | Снимает паузу; после остановки запускает оставшуюся очередь с подтверждением |
| Остановить | Отменяет ожидания и отсчёт, будит приостановленный поток и сохраняет состояние |
| Экспорт JSON | Сохраняет текущий согласованный снимок результатов |

Пауза не разрывает уже выполняющийся Windows UIA-вызов посередине. Если она нажата во время задержки до чтения, обработчик остановится перед следующим действием. В режимах Telegram после **Продолжить** есть пять секунд для возврата в его окно.

Открытие выбора режима или файла после **Начать** останавливает текущую обработку и отменяет отсчёт. Новый TXT загружается после завершения текущей операции. При запуске другого режима создаётся новая очередь только из оставшихся `pending`; готовые результаты не переносятся и не повторяются. Для смены получателя нужен новый запуск из TXT.

При каждом открытии программы путь к файлу и предпросмотр пустые. Это очистка экрана, а не удаление базы. Сохранённую очередь можно продолжить без исходного TXT. В интерфейсе показывается текущий/последний незавершённый запуск; отдельного браузера всей истории нет.

Минимум окна — 480×420. Узкое окно перестраивается в колонку, кнопки — в несколько строк; при недостатке высоты используется вертикальная прокрутка. Поля задержек и select поддерживают клавиатуру. Длинные названия переносятся либо сокращаются многоточием с полной подсказкой.

## 5. Время ожидания и курсор

```text
отправить строку → ждать 3 с → прочитать снимок ответов → ждать 2 с → следующая строка
```

Поля **До чтения ответа** и **После чтения** задают эти две задержки. Их диапазон — 0–3600 секунд. **Разброс задержек ±** — независимое равномерное отклонение обеих задержек, 0–60 секунд; по умолчанию 0.

При базе 2 с и разбросе 0,2 с выбирается значение от 1,8 до 2,2 с. Нижняя граница не бывает отрицательной, верхняя ограничена 3600 с. Кнопки **− / +** меняют значение на 0,1 с без выделения текста; можно ввести число вручную. Настройки сохраняются в базе.

Выбранное время до чтения записывается в `reply_delay_seconds`, время между итерациями видно в журнале. Проверка элементов, вставка, чтение ответа и запись базы занимают дополнительное время: длительность всей задачи может быть больше суммы задержек.

Это один снимок после задержки, а не постоянная подписка. Ответ, пришедший позже снимка, не дописывается к готовому результату. Для медленных ответов увеличьте первую задержку. Разброс не гарантирует отсутствие ограничений Telegram и не заменяет правил сервиса или условий получателя.

Текст вводится через UIA ValuePattern, Clipboard не меняется. После вставки текстовый курсор перемещается в конец через TextPattern; резервный вариант — Ctrl+End в проверенном сфокусированном поле. Указатель мыши для этого не перемещается. Нажимается кнопка отправки, а не Enter, поэтому настройка отправки по Enter не влияет на этот шаг.

## 6. Как программа узнаёт, что сообщение отправлено

До ввода читается история. До нажатия отправки в SQLite сохраняется `send_attempted=true`. Это отметка возможной попытки, а не доказательство доставки. Затем нажимается найденная кнопка и выдерживается задержка.

Новое исходящее определяется по тексту, порядку и количеству вхождений до/после отправки. Одни UIA-идентификаторы недостаточны: строки списка могут пересоздаваться или использовать идентификатор повторно. Для сравнения учитываются NFC Unicode, окончания строк и крайние пробелы. Тексты ответов в экспорт сохраняются исходными, без этой нормализации.

Если исходящее ещё не видно, разрешены два дополнительных чтения с паузой 0,2 с. **Кнопка отправки повторно не нажимается.** Если исходящих кандидатов нет или их несколько, очередь останавливается с диагностикой количества строк/совпадений.

В `messages` попадают все доступные входящие тексты после подтверждённого исходящего. Предыдущие ответы и собственные сообщения исключаются. Одинаковые тексты разных ответов сохраняются отдельно. Число ответов не задаётся заранее: при подтверждённой отправке ноль ответов сохраняется как `[]` и сам по себе не считается ошибкой задачи.

Важные ограничения:

- Доступна только история, раскрытая Telegram через UIA; автоматической прокрутки всей переписки нет.
- Медиа без доступного текста, скачивание вложений, голосовые сообщения, темы и групповые ответы нескольких участников отдельным сценарием не поддерживаются.
- Ответ относится к строке по порядку сообщений, а не по Telegram reply-to ID. Используйте спокойный контролируемый чат.
- Если исходящее исчезло из доступной истории или вся история заменилась идентичной последовательностью, доказать новизну может быть невозможно.
- Разметка и доступность элементов зависят от версии Telegram. Неподдерживаемая версия требует адаптации, а не отключения проверки отправки.

## 7. JSON: что означают поля

Экспорт доступен во время работы. SQLite читается в одной транзакции, поэтому счётчики и задачи относятся к одному снимку. Затем приложение может продолжить обработку: промежуточный отчёт не обязан совпадать с состоянием через минуту.

Формат — UTF-8, с отступами и `ensure_ascii=False`: русский текст виден обычными буквами. Запись идёт сначала во временный файл в выбранной папке, затем выполняется `os.replace`. Ошибка до замены не должна превращать прежний отчёт в половину нового.

Упрощённый пример; реальный отчёт дополнительно содержит идентификаторы и время задач:

```json
{
  "run_id": 1,
  "created_at": "2026-11-23T10:00:00+00:00",
  "total": 1,
  "completed": 1,
  "failed": 0,
  "status": "finished",
  "options": {
    "mode": "chat", "username": "my_test_bot",
    "reply_delay": 3.0, "inter_message_delay": 2.0, "delay_jitter": 0.2
  },
  "records": [{
    "input": "test_001", "status": "completed", "error": null,
    "result": {
      "messages": ["Ответ 1", "Ответ 2"],
      "send_attempted": true, "outgoing_observed": true,
      "reply_delay_seconds": 3.08,
      "reply_complete": false, "completion_reason": "snapshot_after_delay"
    }
  }]
}
```

`completed` — число выполненных **задач**, не сообщений. `outgoing_observed` — исходящее обнаружено. `reply_complete=false` не является ошибкой: программа не определяет, закончил ли собеседник отвечать. `confirmation` содержит количества строк/совпадений и номер чтения. У ошибочной задачи тоже может быть `result`; `error` объясняет остановку. В локальном тесте часть полей реального обмена отсутствует.

Время в БД/JSON — UTC с `+00:00`, в журнале — локальное время Windows. Поэтому часы в журнале и в JSON могут отличаться на часовой пояс.

## 8. База, резервная копия и перенос

Задачи проходят статусы:

| Статус | Значение |
| --- | --- |
| `pending` | Ещё не обработана |
| `processing` | Взята обработчиком |
| `completed` | Сценарий и сохранение выполнены |
| `failed` | Есть ошибка; автоматически повторять нельзя |
| `skipped` | Хранилище поддерживает пропуск; обычный сценарий его не назначает |

`completed` не гарантирует прочтение получателем или полный ответ: снимок может содержать ноль входящих.

Каждая загрузка TXT создаёт новый запуск. Две одинаковые строки — две задачи. Повторная загрузка всего файла может повторить настоящую отправку: не используйте её вместо **Продолжить** без намерения повторить тест.

При перезапуске выбирается последний запуск, отличный от `finished`. Завершённые и ошибочные задачи не выбираются повторно. Оставшаяся после сбоя `processing` возвращается в `pending`, только если отметки отправки нет. Если `send_attempted=true`, она становится `failed`: сообщение могло успеть отправиться. Остановка по кнопке применяет ту же осторожную логику.

Это защита от автоматических дублей, но не exactly-once: SQLite и сервер Telegram не участвуют в общей транзакции. Перед сознательным повтором ошибочной строки сначала проверьте переписку.

Перед резервной копией остановите работу и закройте все экземпляры. Скопируйте всю постоянную папку или как минимум `data\progress.db`. JSON — отчёт для анализа; обратный импорт JSON в очередь не реализован.

Чтобы перенести прежнюю Python-базу в EXE:

1. Закройте обе версии и сохраните резервную копию исходного `telegram_gui_tool\data\progress.db`.
2. Один раз откройте и закройте EXE, чтобы создалась его папка данных.
3. Если у EXE уже есть история, отдельно сохраните его базу.
4. Скопируйте прежний `progress.db` в `%LOCALAPPDATA%\TelegramGuiTool\data\progress.db`.
5. `app.lock` не копируйте. Откройте EXE и проверьте восстановленные счётчики.

Это выбор одной базы, не объединение историй. Рабочая база не включена в поставку и автоматически не переносится из исходников.

При обновлении закройте программу, сохраните копию базы и замените EXE. Постоянную папку данных заменять не нужно. При старте добавляются недостающие столбцы настроек, записи не удаляются. Совместимость с произвольными будущими версиями и понижение версии не гарантированы.

## 9. Ошибки и ограничения

| Симптом | Что проверить |
| --- | --- |
| Telegram не найден | Клиент запущен; процесс называется `Telegram.exe`; нестандартные сборки могут не поддерживаться |
| Потерян фокус | Вернитесь в Telegram во время отсчёта; для перехода к инструменту используйте паузу |
| Username не подтверждён | Точное имя, боковой профиль, RU/EN, развёрнутое окно; не ссылка и не телефон |
| Есть черновик | Сохраните/очистите вручную: инструмент не должен затереть ваш текст |
| Открыт диалог | Закройте его вручную; программа не подтверждает ограничения платформы |
| Элемент найден неоднозначно | Изменился Telegram, есть несколько панелей, нет доступной кнопки |
| Исходящее не подтверждено | Проверьте чат и `confirmation`; не повторяйте вслепую, чтение уже повторялось без отправки |
| Ответов нет | Увеличьте задержку до чтения; возможно, снимок сделан до ответа |
| Неверный TXT | Пересохраните текст в UTF-8, проверьте управляющие символы и предпросмотр |
| SQLite locked | Второй обработчик, права, свободное место и состояние диска |
| Уже запущен экземпляр | Закройте прежнее окно или дождитесь завершения остановки |
| JSON не сохраняется | Выберите доступную папку и проверьте свободное место |
| EXE открывается долго | Подождите распаковку; не запускайте много копий подряд |
| EXE не открыл окно | Посмотрите журнал и выполните `--self-test` по разделу 12 |

Windows UIA-вызов может задерживаться дольше настроенного ожидания. GUI обычно остаётся доступным, но остановка потока ждёт возвращения вызова. После аварийного завершения проверьте переписку вручную.

Журнал не является полным содержимым результата. Сохраняйте время ошибки, версию из `build-info.json` и конкретные строки журнала. Не публикуйте полную базу/JSON без необходимости: они содержат тексты.

## 10. Устройство программы

### Компоненты и потоки

| Модуль | Его задача |
| --- | --- |
| `main.py` | Запуск Qt, журнал, блокировка второго экземпляра |
| `interface.py` | Внешний вид, адаптивные блоки, select и числовые кнопки |
| `main_window.py` | Диалоги, состояние кнопок, запуск/пауза, смена файла/режима |
| `worker.py` | Фоновые QThread для файла, очереди и экспорта |
| `chat_controller.py` | Вставка, курсор, отправка, сравнение истории, ответы |
| `ui_controller.py` | Процесс, активное окно, COM/UIA и диалоги |
| `file_manager.py`, `parser.py` | TXT и фиктивный ответ локального теста |
| `database.py`, `exporter.py` | SQLite, восстановление и JSON |
| `timing.py`, `settings.py` | Разброс задержек, пути, журнал |
| `clipboard_manager.py` | Резервный модуль Clipboard; основной сценарий его не использует |
| `diagnostics.py` | Автономная проверка без настоящих сообщений |

GUI живёт в главном потоке. Чтение TXT, очередь и экспорт — в отдельных QThread; уведомления передаются сигналами Qt, а не прямой записью в виджеты. Condition согласует паузу, Event — остановку. Управляющий запрос проверяется до следующей проверки фокуса.

UI Automation — стандартный доступ Windows к элементам окна. Поиск идёт по типу, структуре и подписи. Основной сценарий не зависит от фиксированных координат. Если InvokePattern отсутствует, клик может выполняться в координатах **свеженайденного элемента**, а не заранее записанной точки.

COM инициализируется в потоке UIA и освобождается после сессии. pywinauto — фактический движок. PyAutoGUI и pyperclip включены как резервные зависимости. Основная отправка/чтение не используют Clipboard, скрытые сессии и API авторизации.

### SQLite и транзакции

- `runs`: `id`, `started_at`, `finished_at`, `total`, `completed`, `failed`, `status`.
- `tasks`: `id`, `run_id`, `input`, `status`, `result`, `error`, `created_at`, `updated_at`.
- `run_options`: `run_id`, `mode`, `username`, `reply_delay`, `inter_message_delay`, `delay_jitter`.

В старой базе могут остаться неиспользуемые столбцы прежних настроек. `result` в SQLite — JSON-строка, в экспортном файле — JSON-объект. Связи задаются внешними ключами; они включаются для каждого соединения. Индекс `(run_id,status,id)` ускоряет выбор pending.

Каждая операция открывает своё соединение с ожиданием занятости базы до 10 с; соединения не передаются между потоками. Взятие pending и перевод в processing используют `BEGIN IMMEDIATE`. Окончательный статус и счётчики обновляются в одной транзакции. Экспорт использует read-транзакцию. WAL специально не включается.

### Журнал и конфиденциальность

`logs\app.log` содержит время, уровень и описание. Максимум одного файла — 2 000 000 байт, до трёх резервных файлов. Обычные ошибки приложения могут содержать traceback. У ошибок UIA сохраняются этап, тип и HRESULT вместо произвольного текста исключения, который может включать переписку. Журнал GUI ограничен 2000 строками и начинается заново.

Пароли и коды Telegram не запрашиваются. Но TXT, предпросмотр, SQLite и JSON содержат тексты открыто и не шифруются приложением. Их защищают права Windows и ваше устройство хранения. Реальная отправка передаёт строку выбранному получателю, даже если само приложение не выполняет сетевые API-запросы.

Проверка предупреждений не всеведущая: доступны видимые модальные/Win32-диалоги и известные структуры Qt. Все нестандартные баннеры Telegram не гарантированно распознаются. Обычное слово «ошибка» в ответе не считается системным предупреждением. При реальных ограничениях не продолжайте автоматические отправки, пока причина не выяснена.

## 11. Запуск из исходников и повторная сборка

Для разработки — Python 3.11/3.12 x64. Команды ниже выполняются **из каталога `telegram_gui_tool`**:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Если окружение находится в родительской папке, замените `.\.venv` на `..\.venv`. Активация окружения и изменение ExecutionPolicy не нужны.

Для сборки EXE на Windows x64:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe build.py
```

`build.py` сначала выполняет тесты, затем запускает PyInstaller по `TelegramGuiTool.spec`, создаёт EXE, manifest, SHA-256 и ZIP. Ошибка шага прекращает сборку. Рабочие файлы — в `build`, готовые — в `dist`. Повторная сборка заменяет одноимённые артефакты `dist`, поэтому старый релиз при необходимости сохраните отдельно.

Для уже проверенного исходного дерева можно передать `build.py --skip-tests`. В manifest это отражается как `source_tests_executed=false`. Точные версии пакетов доступны в `requirements-lock.txt`; совпадение версий не гарантирует побайтово одинаковый EXE из-за особенностей окружения и временных меток.

Используются PyInstaller 6.22.3, one-file, windowed, без UPX. Встроенные данные перечислены явно: графические ресурсы и фиктивный `sample.txt`. **База, app.lock, журналы, пользовательские TXT и результаты не включаются.** Python упаковывается с интерпретатором; это не компиляция всего кода в машинные инструкции и не защита исходников от анализа.

Ресурсы ищутся относительно `__file__`, постоянные данные — отдельно. Это соответствует [документации runtime-путей PyInstaller](https://pyinstaller.org/en/stable/runtime-information.html). Динамические COM/UIA-модули добавляются как hidden imports.

## 12. Проверки и диагностика EXE

Исходники проверяются командой:

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
Remove-Item Env:QT_QPA_PLATFORM
```

Проверяются кодировки, отмена, парсер, SQLite/миграции, восстановление, JSON, подтверждение отправки, задержки/разброс, курсор, кнопки управления, смена файла/режима и компоновка. Внешние действия Telegram подменяются контроллером: тесты не отправляют сообщения.

Скрипты `tests\verify_startup.py` и `tests\verify_layout.py` сохраняют изображения в `exports`. Геометрия проверяется для 480×420, 640×480, 800×600, 1080×900, 1440×1000, 1280×520: длинные подписи, прокрутка, отсутствие горизонтального переполнения, работа select клавиатурой.

У готового EXE есть автономная проверка. Из папки с EXE:

```powershell
$report = Join-Path $PWD 'exe-self-test.json'
$process = Start-Process -FilePath .\TelegramGuiTool.exe `
  -ArgumentList '--self-test', ('"' + $report + '"') `
  -WindowStyle Hidden -Wait -PassThru
$process.ExitCode
Get-Content -LiteralPath $report -Encoding UTF8
```

Она не запускает Telegram, не меняет Clipboard и не отправляет сообщения. Используется временная база с фиктивными данными. Проверяются Windows-зависимости, создание COM/UIA-объекта, TXT, локальная очередь, экспорт/восстановление, встроенные ресурсы, отрисовка Qt и шаг числового поля. Рядом с JSON сохраняется PNG окна без показа на экране.

Код 0 и `success=true` — успех; код 1 — ошибка проверки; код 2 — не указан путь отчёта или его не удалось записать. Рабочая `progress.db` не используется. Self-test доказывает работу упакованных компонентов, но не заменяет обмен с конкретной версией Telegram. Полный новый обмен с настоящим получателем при сборке не выполняется.

Перед эксплуатацией на другом компьютере проверьте локальный режим и одну согласованную тестовую строку. Версии компонентов, архитектура, время сборки и контрольная сумма доступны в `build-info.json`.
